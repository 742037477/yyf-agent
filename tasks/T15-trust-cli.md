## Goal
Stage 2. T14 built the signing library (`m2k/trust.py`). This card gives the owner the tools to use it:
- create test keys;
- sign a framework charter and a revocation list with a Root key;
- describe the trust setup in `m2k.toml`;
- check that setup with one command.

It also adds the loader that T16 uses to wire the chain into the kernel. Nothing here runs a task.

Security rules for this card:
- A private key is never printed, logged or copied.
- An existing file is never overwritten.
- A `PRODUCTION` Root key is never generated by this tool: the real Root is made and used offline on the USB key.

## Required behaviour
1. `m2k/trust.py` additions (keep every T14 test passing unchanged):
   - `verify_charter(pin, domain, charter_env, revocations_env, code_dir) -> (charter_body, revoked)`.
     - It runs exactly the first five checks of `verify_chain`, with the same codes: DOMAIN, CHARTER_SIGNATURE,
       REVOCATIONS_SIGNATURE, CHARTER_REVOKED, RELEASE.
     - `revoked` is `{"revoked_charters": [...], "revoked_credentials": [...]}`.
     - `verify_chain` must call it instead of repeating those checks.
   - T14 review leftovers:
     - a charter whose `issuer_public_key_b64` is malformed gives `FORMAT`, not `KEY`, inside `verify_charter` / `verify_chain`;
     - `load_pin` on a file that is not a JSON object, or not UTF-8, raises `TrustError("FORMAT")`;
     - `fingerprint` / `public_key_sha256` in a pin must equal the full computed value exactly. Both are full hex:
       `fingerprint` is 16 characters, `public_key_sha256` is 64.
   - `TrustSetup` and `load_setup(section: dict, base_dir: Path) -> TrustSetup`, built from the `[trust]` config table
     (paths are relative to the config folder):
     ```
     [trust]
     domain = "TEST_ONLY"                 # or "PRODUCTION"
     root_pin = "keys/root-pin.json"      # Root public key
     charter = "keys/charter.json"        # Root-signed framework charter
     revocations = "keys/revocations.json"  # optional, Root-signed
     issuer_key = "keys/issuer.pem"       # the framework's own private key; never inside a task workspace
     credential_ttl_s = 3600              # optional
     ```
     - `TrustSetup` holds `domain`, `pin`, `charter_env` (parsed with `loads_strict`), `revocations_path`,
       `issuer_key_path` and `ttl_s`.
     - Method `revocations()` re-reads the revocations file on every call (`None` if not configured), so a revocation
       issued mid-task takes effect.
     - Method `issuer_key()` loads the private key.
     - A missing or bad file, an unknown domain or a missing required key raises `TrustError` with a clear message.
2. `m2k trust` sub-commands in `m2k/cli.py`:
   - **`keygen --role root|issuer --out PREFIX [--domain TEST_ONLY|PRODUCTION]`**
     - Writes `PREFIX.pem` (unencrypted PKCS#8; on POSIX, file mode 600) and `PREFIX-pin.json`
       (`{"schema": "m2k.pin/1", "trust_domain", "public_key_b64", "fingerprint"}`). Prints the pin path and fingerprint.
     - `--role root` with `--domain PRODUCTION` exits 2 with:
       `正式 Root 只能在离线环境用自己的工具生成；本命令只生成 TEST_ONLY 的 Root`.
     - Default domain is `TEST_ONLY`.
   - **`sign-charter --root-key PEM --issuer-pin PIN --caps CAPS.toml --domain D --out FILE [--release dev|current] [--charter-id ID]`**
     - `CAPS.toml` holds `tools`, `max_rounds`, `max_model_calls`, `max_tokens`, `max_commands` and `network`.
     - `current` = `release_digest` of the installed `m2k` package folder; `dev` under `PRODUCTION` exits 2.
       The default release is `dev` for `TEST_ONLY` and `current` otherwise.
     - `charter_id` defaults to a random hex id; `issued_at` = now.
     - After signing, the command re-opens the envelope with the Root public key as a self-check, then writes `FILE`.
   - **`sign-revocations --root-key PEM --domain D --version N [--charter ID ...] [--credential ID ...] --out FILE`**
   - **`status`**
     - Reads `[trust]` from the config and prints: domain, Root fingerprint, charter id, issuer fingerprint, caps,
       release (`dev` or "matches this code" / "does not match"), the revocation list version, and whether
       `issuer_key` matches the charter's issuer.
     - Exit 0 when `verify_charter` passes and the issuer key matches; otherwise print the `TrustError` code and exit 1.
       A missing `[trust]` section prints `no [trust] configured` and exits 1.
   - Every command refuses to overwrite an existing output file (exit 1, message names the file).
3. Docs:
   - `m2k.example.toml` gets the commented `[trust]` block above.
   - `README.md` gets a short "信任链" section: the five-line test setup (keygen root, keygen issuer, write caps,
     sign-charter, status), and one sentence that the production Root is never generated or stored on this computer.

Tests use temporary folders and freshly generated keys. Required cases:
- The full test setup through the CLI ends with `status` exit 0.
- `keygen --role root --domain PRODUCTION` exits 2 and creates no file.
- Overwriting is refused.
- A tampered charter gives `status` exit 1 with `CHARTER_SIGNATURE`.
- A revoked charter gives `CHARTER_REVOKED`.
- An issuer key that does not match the charter gives exit 1.
- `sign-charter --release dev --domain PRODUCTION` exits 2.
- `revocations()` sees a file written after `load_setup`.
- No command's stdout or stderr contains the private key PEM body.
- Each T14 leftover has a test.
